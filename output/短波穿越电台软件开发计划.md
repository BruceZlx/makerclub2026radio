# 短波穿越电台软件开发计划

版本：1.1  
日期：2026年11月24日  
面向：软件组、partner 及接续开发的 AI  
用途：确定实现顺序、模块边界、联调规则与验收依据。物理 IO 接口分配全部留空。

本项目采用双 ESP32 架构。板 A 管理旋钮、选城、网络、音频与待机，板 B 负责地图和动画。partner 已确认单城市电台闭环完成，下一阶段直接复用现有工程，补齐多城市切换、主备与 SD 卡策略、双板通信、显示、异常恢复和测试的完整代码。城市内容页本轮暂不编写，物理 IO 分配继续留空。

本版落实 partner 最新反馈：选城后立即并行连接、解码、缓冲与播放地图动画；旋钮转动是最高优先级的用户中断；明确连接或解码失败立即切源，确认断网直接转 SD 卡；软件自行选取较宽松的连接超时初值。MAX98357 I2S 音频放大器模块已确定。已确认规则与新增建议分别记录在第 13 节。

相对 1.0，本版取消“从零跑通单城闭环”的开发任务，主、备用首播预算改为各 15 秒，独立按键全部更正为旋钮按压，并将首次加载与 20 秒待机的冲突作为一项明确的产品规则建议。

## 1 项目目标与当前基线

### 最终体验

设备开机进入待机动画。用户旋转旋钮选择城市后，立即开启该城市电台连接、解码和缓冲，同时显示从上海到目标城市的弧线。弧线抵达且音频准备完成后解除静音。主用电台明确失败或超过首播预算时切备用；备用也失败时播放本地文件；确认网络断开则跳过主备，直接播放该城市 SD 卡音频。活动播放期间 20 秒没有有效用户操作后返回待机；首次加载期间的计时例外见第 5 节及 R2，该例外属于本版新增待确认建议。

设备只有可转动、可按压的同一个旋钮，没有独立按键。后续产品交互保留“按压旋钮进入城市内容页，再次按压返回地图”，但 partner 已明确内容页代码本轮先不写。本轮只实现旋钮 SW 消抖与 ENCODER_PRESS 事件，按压可刷新活动时间，不进入空白页面、不重连电台；页面绘制、切页逻辑、当地时间与内容字库延后。

项目名称中的“短波”用于作品命名。当前方案通过 Wi-Fi 获取互联网电台，不包含射频接收、调谐或真实短波频率控制。

### 计划采用的默认规则

1. 直接接续 partner 已完成的单城工程，锁定 Arduino 与 ESP32-audioI2S 环境；本轮补齐其余核心代码，不重做可行性验证。
2. 板 A 是城市、页面、音频来源和待机状态的唯一决定者；板 B 根据状态显示并报告动画进度。
3. 选城即发起连接、解码和有界缓冲，不等待动画结束，也不增加人为的选城停顿。静音期间持续读取、解码和消费实时音频，避免堆积成历史声音。
4. 主、备各有 15 秒首播预算；明确连接或解码失败立即切换，不等满 15 秒；确认网络断开直接转 SD 卡。播放中无采样进度采用独立的 10 秒断流初值。
5. 旋钮转动优先于音源切换、连接超时、显示通知和待机处理。首次加载有界，建议首次出声后再获得完整 20 秒无操作时间；已开始播放后的自动切源与网络事件不续期待机。R2 明确区分新增建议与原规则。
6. 协议 v2 是推荐实现目标；v1 原格式保留在文档中用于迁移核对，不混用两套解释。
7. 离线文件循环播放至新操作或待机；本轮不在离线播放时频繁尝试抢回在线电台。

partner 已授权软件自行选取较长的连接超时，因此本版选取每源 15 秒，不再把具体秒数作为必须由 partner 决定的事项。该值是工程初值，不是行业标准；所有时间参数集中配置并由首播时间日志微调。两级各 15 秒与最后操作后 20 秒待机存在直接冲突，故 R2 单列加载期例外；它不能被误写为 partner 已确认。

## 3 软件架构和工程组织

### 模块职责

| 模块 | 所属 | 职责及边界 |
| --- | --- | --- |
| AppController | 板 A | 处理事件、生成请求编号、决定选城、页面、来源、出声和待机 |
| InputService | 板 A | 同一旋钮的 A B 相解码、卡点换算和 SW 消抖；旋转事件优先发布 |
| AudioAdapter | 板 A | 独占音频对象，封装在线与文件播放、静音、停止及音频进度 |
| SourceManager | 板 A | 主用、备用、离线的单向切换和各阶段超时 |
| WifiService | 板 A | 非阻塞连接状态、断线事件与后台重连，不直接决定页面 |
| SdAudioCatalog | 板 A | 检查挂载、文件存在与文件结束，不替代播放器解码 |
| LinkService | 两板 | 有界分帧、协议编解码、握手、确认、状态重发 |
| DisplayController | 板 B | 接收状态快照，取消旧动画，本轮实现待机与地图；内容页仅保留扩展边界 |
| MapRenderer | 板 B | 缓存底图、绘制弧线与光点，不执行网络或音频操作 |
| CityCatalog | 共享 | 提供稳定城市编号、位置、显示内容与配置版本 |

选城事件路径：旋钮转动 → 板 A 控制器 → 音源准备与板 B 显示并行执行 → 收到当前请求的音频就绪和动画完成 → 板 A 解除静音。旋钮按压走独立的输入事件路径，本轮不启动选城或音源准备。音频采样数据仅在板 A 与音频输出模块之间流动，不通过板间串口传输。

### 主循环和并发约束

保持音频对象的高频服务调用。锁定库版本提供的 `audio.loop()` 应持续运行，输入、UART、超时和状态事件也必须持续处理。禁止使用长时间 `delay()` 或等待 Wi-Fi、DONE、音频首帧的空转循环。

M0 测量 `connecttohost()`、`stopSong()`、SD 打开与 TLS 等调用的最长阻塞。函数名含 connect 并不保证异步；单独设置 TCP 超时也不等于控制了 DNS、重定向及内部重试的总时长。若调用阻塞超过响应目标，需要在 AudioAdapter 内采用受控工作任务或针对锁定库的小范围适配，并重新验证超时、取消和看门狗。

Audio 对象的控制 API 只能由一个所有者调用。不能从输入任务、UART 任务和回调中并发执行停止、切源和音量设置。采样回调只更新原子计数或写入有界事件队列，不能打印长日志、操作文件、联网或切源。

### MAX98357 音频接口

输出链路为 ESP32 解码得到 PCM，经 BCLK、LRCLK 与 DOUT 三个 I2S 信号进入模块，DOUT 对应模块 DIN。按已确认的 I2S 模块路线不增加独立模拟 DAC，也不要求 MCLK。音量和静音在音频适配层统一控制；静音不能停止解码与健康检测。

模块若只驱动一只喇叭，应复用现有可出声工程的声道配置，并验证立体声节目两侧都能听到，避免误丢一侧内容。GAIN、SD_MODE 的物理设置由硬件配置确定，不默认额外需要一个 MCU 控制脚。MAX98357A 使用标准 I2S，MAX98357B 使用左对齐格式；对后缀做接收核对，不更改已验证可用的时序。来源见 S8，所有实际 GPIO、接线和供电分配继续留空。

## 5 交互和状态模型

### 分开记录页面和音频状态

页面状态为 STANDBY、MAP、INFO；动画状态为 NONE、RUNNING、DONE；音频状态为 IDLE、CONNECTING、BUFFERING、READY_MUTED、PLAYING、ERROR。音源为 NONE、MAIN、BACKUP、LOCAL。这样可以表达“地图已到达但仍在连接”或“离线音频已准备好但动画未结束”，避免将所有状态压成一个数字。

每次有效选城创建新的 `requestId`，即使选择的城市与之前相同也必须生成新编号。每次主、备或离线尝试另建内部 `attemptId`。板 A 每次启动生成新的 `sessionId`，防止设备重启后旧消息被误认成当前请求。

### 事件与动作

| 事件 | 板 A 动作 | 板 B 动作 |
| --- | --- | --- |
| 开机 | 自检，静音，页面设为待机，后台连接 Wi-Fi | 启动待机动画，等待握手与状态 |
| 旋钮有效移动一格 | 更新城市和请求编号，立刻静音并取消旧请求，页面转地图，启动音频准备 | 停止旧动画，为新请求绘制弧线 |
| 当前音频就绪 | 更新 READY_MUTED，检查动画条件 | 展示连接或来源状态，不自行开声 |
| 当前动画完成 | 校验会话和请求，满足出声条件时进入播放 | 保持地图，发送 DONE 并等待确认 |
| 旋钮短按 | 本轮仅发 ENCODER_PRESS 并刷新活动时间，不切源；内容页暂缓 | 保持现有地图或待机，不进入未实现的 INFO 页 |
| 主或备启动失败 | 停旧尝试并清缓冲，进入下一来源 | 保持当前城市，不重播弧线 |
| Wi-Fi 确认断开 | 停止在线尝试，直接准备本地文件 | 标明离线来源 |
| 待机计时满 20 秒 | 静音、停止音源、使旧请求失效，发布待机状态；首次加载规则见 R2 | 取消当前页面和动画，返回待机 |
| 待机后旋钮转动 | 新建请求并选择相邻城市，立即开始当前城市的来源准备 | 显示对应地图动画 |

本轮由转动旋钮唤醒和选城；没有有效选城时使用配置首城作为索引基准。活动状态的旋钮短按只记录事件并刷新活动时间，待机短按暂不增加未要求的唤醒行为。后续内容页启用后，再将同一个 ENCODER_PRESS 事件接入 MAP 与 INFO 切换。

旋钮转动和按压在联网、动画、播放和失败状态下持续采集；没有独立按键。旋钮短按在完整按下与释放后上报一次，50 ms 为消抖初值；长按暂不映射功能。旋钮每卡点的有效边沿数以实测标定，不将“每格必定为 4”写成所有编码器的硬规则。

### 旋钮转动的最高优先级

任一有效卡点先更新城市与 requestId，关闭旧音频输出门控，标记旧连接、解码和动画请求失效，再立即调度新城市的来源准备及地图动画。同一调度周期内先处理旋转，随后才处理当前请求的断网、明确失败、超时、显示完成及待机事件；这些事件都以旋转后的最新城市为准。

该优先级是逻辑抢占关系，不是在 GPIO 中断服务中执行 HTTP、SD、解码或串口发送。硬件中断只采集相位和计数，由控制任务消费。快速旋转时可丢弃尚未执行的旧连接任务，不能让任务排队逐城播放，也不能等待旧连接的 15 秒预算结束才响应新选择。

现有库若存在不可取消的长阻塞，需在 AudioAdapter 内分段等待或适配取消边界。输出门控使用可及时更新的代次标记；不得靠强制删除任务或并发操作同一 Audio 对象实现抢占。控制状态更新和旧声音停止目标仍为 100 ms，取消完成与新连接启动的实测延迟单独记录；未达到时要修正阻塞点。

### 出声条件和取消条件

```text
允许出声 = 当前处于活动状态
        且 音频属于当前 session request attempt
        且 当前音频已就绪并持续有有效采样进度
        且 当前动画已完成或已明确进入显示失联降级
```

新选城、待机、切源和致命错误优先关闭出声，再处理资源释放。旧请求的 DONE、首帧、失败和文件结束事件一律忽略。只比较城市号不足以避免“城市 1 → 城市 2 → 城市 1”的旧通知问题。

AudioAdapter 停止旧播放后，应确认旧任务与缓冲已停止或隔离，再启动新尝试。库回调若不携带请求身份，不能在回调里简单读取最新编号并给旧采样贴上新标签；须通过串行切换、回调排空及代次隔离建立明确边界。

### 计时参数

| 参数 | 初值 | 计时起点与含义 |
| --- | --- | --- |
| MAIN_START_TIMEOUT | 15000 ms | 主用尝试启动至就绪，覆盖 DNS、连接、响应、缓冲、解码及内部重试 |
| BACKUP_START_TIMEOUT | 15000 ms | 备用尝试启动至就绪，独立预算；明确失败提前结束 |
| STREAM_STALL_TIMEOUT | 10000 ms | 最近一次有效 PCM 进度；处理未明确断网的持续卡流 |
| WIFI_INITIAL_TIMEOUT | 15000 ms | 开机后台首次连 Wi-Fi 的单轮上限；选城时无可用网络直接走 SD |
| LOCAL_START_TIMEOUT | 2000 ms | 启动本地文件，至音频就绪；仅为计划初值 |
| TOTAL_START_TIMEOUT | 32000 ms | 本次选城至首播或最终失败的总预算，不因切备用或重定向重置 |
| IDLE_TIMEOUT | 20000 ms | 正常播放后从最近操作计时；首次加载例外按 R2 建议处理 |
| ARC_DURATION | 1500 ms | 板 B 启动当前弧线；仅为计划初值 |
| DISPLAY_DONE_TIMEOUT | 3500 ms | 发布新选城；超时重发快照并标记显示降级 |
| SNAPSHOT_INTERVAL | 1000 ms | 活动期间重发当前全状态，用于丢包与重启恢复 |
| DONE_RETRY_INTERVAL | 250 ms | 板 B 完成动画后重发 DONE，最多重发 8 次 |
| INPUT_RESPONSE_TARGET | 100 ms | 有效输入到状态更新、旧音源静音的实测目标 |

连接时间采用 15 秒的理由是保留对较慢 DNS、TLS 与首播缓冲的容忍，同时用单源上限和总加载上限避免无限等待。主备均无明确失败时最多占用约 30 秒，SD 启动再预留 2 秒；这是产品体验初值，后续根据成功源首播耗时分布调整，不将正常慢台误判为坏台。对单次底层阻塞另设短超时与取消检查，不允许一次阻塞占满整个 15 秒并卡住旋钮。

首次加载待机策略新增建议为 AFTER_INITIAL_LOAD：一次用户选城创建的初始加载期间暂缓自动待机，但仍受 32 秒总预算限制；首次解除静音后，从首播时刻与最后有效用户操作中较晚者起计 20 秒；所有来源失败时，从进入 ERROR 起计 20 秒。该建议由软件提出，R2 尚待确认，不属于 partner 原话。

同一请求已经出声后发生自动切源，不重新暂停或延长待机；Wi-Fi 恢复、DONE 和后台重试不续期。可保留 LAST_USER_INPUT 策略作为兼容选项，此时最后操作后满 20 秒就取消加载，意味着无法完整等待两级各 15 秒。两种策略必须在配置和测试中明确，禁止同时声称满足。毫秒计时用差值法验证回绕；后台联网不唤醒待机。

## 6 音频与离线策略

### 接续现有播放器

单城电台闭环已经完成，本轮直接把现有工程纳入 AudioAdapter，保留已跑通的网络、MAX98357 I2S、分区和缓冲配置。只补多源管理、取消、就绪检测和外层调度所需接口；不另起一个播放器重做单城闭环。若现有工程也含 SD 播放，直接复用其接口，若未含则仅补本地来源支持。

锁定版本 4.0.1 的公开接口包含 `connecttohost()`、`connecttoFS()`、`setConnectionTimeout()`、`setMute()`、`loop()` 和 `stopSong()`。正式调用签名仍以 M0 收到的实际库副本为准。来源见 S4。

### 音频就绪和健康判定

HTTP 成功、收到了字节、`isRunning()` 为真以及采样率已知，都不单独等价于已能播放。计划使用音量处理前的有效 PCM 采样进度作为软件就绪和健康依据，辅以运行中的缓冲状态；喇叭是否实际出声仍需实机听音确认。

官方 4.0.1 源码提供 `audio_process_raw_samples()` 采样钩子，并在增益处理前调用。先用该钩子累计有效采样和最近进度时间，静音期间也能判断链路是否在工作。建议连续约 200 ms 采样进度后标记 READY_MUTED，避免仅凭一次回调放行。此阈值需 M1 实测。回调不做音量大小判断，节目中的自然静音不触发切台。来源见 S4 与 S5。

M0 还应验证静音 API 的实际行为。若选用的静音方式停止采样消费，应改为适配器中的输出门控，使解码持续运行；不能因“静音”而停止整个播放器，也不能在同步等待期间无限缓存实时音频。

### 失败分类与调参日志

连接被拒绝、无效地址、无法访问的响应、实际不支持的编码、解码器确认无法继续等明确失败，收到后立即切源，不等完整 15 秒。单个可恢复坏帧或短暂无数据不等于解码失败，应遵循锁定库的错误分类；自然静音也不是失败。没有明确错误但一直无法形成可播放 PCM，才使用首播预算。

系统 Wi-Fi 断开事件优先于电台错误和普通卡流计时，确认断开后取消当前在线尝试，直接准备当前城市 SD 文件。仅有一个台址超时不能当作全网断开；仍然关联 Wi-Fi 但上游无网时，通过连接失败和有界首播预算处理，不因一次探测失败跳过全部备用源。

分别记录 DNS 开始、连接结果、首字节、首个有效 PCM、音频就绪、动画完成、解除静音、失败原因和实际切源时刻。后续按每城成功请求的耗时分布及现场体验调整 15 秒初值；参数集中在一个配置位置，禁止散落在多个循环中。

### 切源顺序

1. 选城时 Wi-Fi 可用则立即开始 MAIN。明确连接或解码失败立即进入 BACKUP；没有明确错误但持续未就绪，则在 15 秒预算到期后切换。
2. BACKUP 使用独立的 15 秒预算；明确失败或预算耗尽后立即进入 LOCAL。总加载上限维持 32 秒，不因切源重置。
3. 选城时网络不可用，或任意在线阶段收到确认的 Wi-Fi 断开事件，直接进入当前城市 LOCAL，跳过主备及其剩余等待。
4. LOCAL 检查 SD 挂载、当前城市文件、解码首帧和循环播放。失败则进入 ERROR，显示“音源暂不可用”，输入与待机计时继续工作。
5. 已经播放 MAIN 时明确解码或连接失败立即切 BACKUP；没有明确错误但连续 10 秒无 PCM 进度也切 BACKUP。BACKUP 同类故障转 LOCAL；若确认为断网，直接 LOCAL。同一次选城不循环主备，自动切源不续期待机。
6. 在线音源等待期间、离线切换期间仍遵守同一出声条件。备用和离线准备完成不要求重播地图动画，也不要求再收到一次新的 DONE。

保持已成功的离线播放时，可在后台做有退避的 Wi-Fi 重连；本轮默认只在下一次用户选城时重新尝试在线源。若用户要求自动恢复在线，再实现独立的 P1 回切策略和防抖时间。

### 音频资源规范

优先让在线源采用目标板已验证的直接 MP3 流，其他编码或播放列表必须单独测试，不因浏览器能播就判定支持。离线资源先统一为 MP3、44.1 kHz、固定码率 128 kbps；如实测需要调整，以统一规格重新验收，不混入未经测试格式。

每城对应一个稳定文件路径，文件名使用城市代码而非显示顺序。记录时长、格式、码率、来源和使用说明。文件结束自动循环；文件丢失、损坏、SD 挂载失败不应引起死循环或重启。本轮只保证启动缺卡和读取失败的处理，不承诺未经硬件验证的带电热插拔。

## 7 板间逻辑协议

### 原协议和升级原因

交接文档记录 v1 采用 115200 波特率和换行分帧：

```text
A -> B  ST:<city>:<state>\n
B -> A  DONE:<city>\n
A -> B  BTN:<city>\n
```

v1 状态值为 0 待机、1 调台、2 连接中、3 播放、4 离线、5 内容页。它可以忽略另一个城市的 DONE，但无法识别返回同一城市后的旧 DONE，也没有重启后的状态恢复机制。原记录中的 BTN 是切换指令，重复接收可能再次翻页。

因此建议在两板尚未实现通信时统一升级到 v2。该升级属于本计划新增建议，需在 R3 确认目标版本。若继续使用 v1，应明确接受上述限制，不能宣称通过同城往返与重复报文验收。

### 推荐的 v2 报文

使用 ASCII、冒号分隔和 LF 换行；接收端可兼容行末 CRLF。最大帧长 160 字节，包含换行。波特率沿用 115200，逻辑配置 8N1；物理 IO 仍留空。

```text
HELLO:2:<board>:<boot>:<config>\n
ST:2:<session>:<request>:<city>:<view>:<anim>:<audio>:<source>\n
DONE:2:<session>:<request>:<city>\n
ACK:2:<session>:<request>:DONE\n
```

| 字段 | 约定 |
| --- | --- |
| board | A 或 B |
| boot | 本板本次开机标识，16 位十六进制文本 |
| session | 当前板 A 的 boot 标识；板 B 原样回传 |
| request | 板 A 分配的递增无符号 32 位请求编号 |
| city | 稳定城市编号 0 至 7，配置表不随显示排序重编号 |
| config | 公共城市和显示配置的版本校验标识，8 位十六进制文本 |
| view | 本轮启用 STANDBY MAP；INFO 仅保留协议枚举，本轮不发送也不渲染 |
| anim | NONE RUNNING DONE，表示本次弧线是否仍待完成 |
| audio | IDLE CONNECTING BUFFERING READY PLAYING ERROR |
| source | NONE MAIN BACKUP LOCAL |

v2 不复用 v1 的数字状态解释。板 A 用 ST 全量状态快照指定目标页面，替代具有翻转副作用的 BTN。发来的相同状态可以重复应用；仅 source 或 audio 改变时不能重启动画。

### 可靠性和重启处理

1. 开机双方发送 HELLO，未握手时定期重发。配置版本不一致时明确报错，不按错误编号展示另一座城市。
2. 板 B 接收同一会话中新于当前值的 request 后取消旧动画，低于当前值的旧 ST 直接丢弃。相同 request 的重复 ST 只更新状态；已完成动画则重发 DONE，不重新播放。只有握手确认板 A 会话改变后，才接纳另一 session 的状态。
3. DONE 必须同时匹配 session、request 和 city。板 A 接受后发送 ACK；重复 DONE 仍回复 ACK，但只执行一次状态转移。
4. 板 A 周期发送 ST。板 B 重启后，若快照 anim 为 DONE，直接恢复静态地图；内容页留待后续启用；若为 RUNNING，可从头重播当前请求的弧线并返回 DONE。
5. 3500 ms 未收到有效 DONE 时，板 A 重发状态并记录显示降级，允许已就绪音频出声以避免永久静音。partner 已接受统一同步与避免永久静音的处理方向；3500 ms 是可调实现初值，见 R4。故障恢复后重同步当前状态，不能播放旧城市。
6. 超长帧、字段缺失、非法枚举、越界编号和旧会话消息全部丢弃并计数。分包和粘包正常缓冲至换行；不要用会长时间阻塞的整行读取等待接收结束。
7. request 接近回绕时在安全停止后重新生成 session 并握手，不直接按普通整数大小比较跨回绕请求。

协议版本不匹配时明确报错并保持可恢复状态，不默默把 v1 当 v2 解析。若需要兼容旧固件，用明确构建选项选择版本，两板成对发布。

### 典型同步时序

```text
用户             板 A                    板 B
旋转一格         新 request 静音
                 ST MAP RUNNING   ---->  开始弧线
                 同时连接并解码
                 音频 READY 静音
                                   <----  DONE 当前 request
                 ACK DONE         ---->
                 校验双条件并出声
                 ST MAP DONE      ---->  保持地图
```

若 DONE 先到，板 A 保持静音直到音频就绪；若音频先到，则继续静音解码直到 DONE。任一阶段收到新选城或待机事件，旧时序立即失效。

## 8 屏幕和城市数据

### 地图与动画

屏幕到货前用逻辑坐标或电脑预览验证世界地图、上海起点、城市落点、弧线插值与页面状态。实屏到货后再确定物理分辨率、扫描方式、色深和刷新库；这些参数不能由交接中“HUB75”一词直接推定。

底图采用代码绘制并缓存，运行时只更新弧线、光点、文字与局部变化。按屏幕能力选取缓存方式，不能承诺所有图形缓冲都能放入 PSRAM。刷新、DMA 与字库的内存和驱动限制须用最终板型验证。目标动画帧率先取 20 至 30 fps，最终以无明显闪烁、无刷新阻塞和内存稳定为准。

采用简单经纬度投影，将经度映射为横坐标、纬度映射为纵坐标，上海为固定起点。确认跨日期变更线时弧线的绘制策略，所有城市点位由内容组核对。显示坐标与电台网络地址相互独立，切源不改变地图位置。

### 城市配置

`cities.json` 是唯一编辑源，生成板 A 与板 B 需要的公共数据及相同 config 标识。板 B 不必保存电台 URL，文件路径和显示顺序也不应充当城市身份。

| 字段 | 用途和校验 |
| --- | --- |
| id code name | 稳定编号、文件用代码、城市中文名；编号与代码唯一 |
| longitude latitude | 有符号坐标；检查合法范围并人工核对落点 |
| primaryUrl backupUrl | 去掉首尾空白，要求真实直链或经实机验证的播放列表 |
| primaryStation backupStation | 分别记录主、备用台名，切源后显示实际台名 |
| offlinePath offlineLabel | 当前城市离线文件路径和“离线录音”等来源标签 |
| timezoneRule | 时区规则或经验证的转换标识，不能只有固定整数时差 |
| copy | 城市主页的一行文案，按屏幕字数限制校验 |
| displayOrder | 旋钮浏览顺序，与 id 分开 |
| streamProfile | 可选记录编码、标称码率及认证需求，供测试与诊断 |

交接示例里的台名和“频率”字段并不一致，不能照抄示例数字。该字段只在内容组确认后作为展示文案保留，不参与互联网电台切换。

### 城市资源验收

每条地址记录目标板、软件版本、测试网络、日期、最终 URL、编码、首播时间、持续播放时间和结果。主用与备用分别测试；“6 城通过”不足以证明其备用源也通过。巴黎与开罗先替换候选源，再按相同标准测试。未拿到完整表前不猜测其余城市名单。

每城主用至少稳定播放 20 分钟，备用至少 5 分钟，离线至少完整循环两次；通过后，在展示场地网络重新抽查。主备最好避免完全相同的失效路径，但实际可用性以现场测试为准。

### 当地时间

### M0 接收并封存已完成的单城工程

依赖：partner 的完整出声源码、库副本、构建脚本、实际目标板和已知可用音源。

工作：接收现有源码、环境与资源，封存已完成单城成果；做短时构建上传冒烟，核对 PSRAM、实际库版本及 MAX98357 设置；测量音频 API 的取消边界、静音行为与采样钩子。保留已有持续播放证据，将长时间回归安排在新增代码集成后；不再安排从零完成单城播放。

输出：基线源码快照、environment.lock.md、冒烟与调用耗时记录、缺失材料清单。验收：能在既有工程上继续开发，播放路径可回退，单城成果不被重写。估算 0.5 人日，仅计接收与集成准备。

### M1 复用播放链路并补齐音源适配

输出：音频适配层、单城演示、首帧与停止时间日志。验收：在线与本地均能出声，切换不遗留旧声音，静音时仍可判定就绪，坏文件不会卡死。估算 0.5 至 1 人日。

依赖：M0 的可用工程与旋钮实物；可先用串口输入模拟选择。

输出：AppController、SourceManager、逻辑测试及实机故障注入记录。验收：主用故障切备用、双故障切离线、断网直接离线、自然静音不误切；待机后不会因旧事件出声。估算 1.5 至 2.5 人日。

输出：共享协议模块、显示模拟端、协议说明和抓取日志。验收：城市往返不接受旧 DONE；重复快照不重启动画；A 或 B 重启后恢复当前权威状态；超长帧不撑爆缓冲。估算 1 至 1.5 人日。

## 10 测试与验收

### 测试层次

主机逻辑测试覆盖有真实竞态风险的状态机、协议、计时和配置校验，使用可控时钟与模拟音频事件。实机测试覆盖 PSRAM、编译上传、旋钮电气行为、真实解码与出声、SD、UART、屏幕和供电。不能用“单元测试通过”替代喇叭与屏幕验收。

### 必测用例

| 编号 | 场景 | 验收结果 |
| --- | --- | --- |
| T01 | 原播放器基线 | 目标环境连续出声至少 20 分钟，无异常重启 |
| T02 | PSRAM 或硬件配置缺失 | 有明确错误提示，不进入不可控播放或静默采用默认 IO |
| T03 | 旋钮正反转及抖动 | 一卡点一城市，首尾循环，未形成有效步进不换城 |
| T04 | 动画先结束 | 等到当前音频就绪才出声 |
| T05 | 音频先就绪 | 解码继续运行，动画结束前保持静音 |
| T06 | 城市 1 到 2 再到 1 | 旧城市 1 的 DONE 和音频回调不能放行新请求 |
| T07 | 20 次快速换城 | 最新城市胜出，旧音频停止，无残留连接堆积 |
| T08 | 主用或备用明确失败与无首帧 | 硬失败立即切下一源；无首帧各自不超过 15 秒预算加调度误差 |
| T09 | 主备均不可用 | 转当前城市本地文件，来源显示正确 |
| T10 | 选城时无网或在线阶段断网 | 旋钮仍最高优先级；确认断网即调度当前城市 SD，不再等主备预算 |
| T11 | 播放中断流及自然静音 | 持续无采样进度按规则切源；正常静音节目不误切 |
| T12 | SD 缺失 缺文件 损坏文件 | 显示可用错误状态，无无限重试和崩溃 |
| T13 | 本地文件结束 | 正常重新播放，不转错城市 |
| T14 | DONE 丢失 重复 延迟 | 重发和确认有效；只有当前请求可改变出声条件 |
| T15 | 分包 粘包 超长帧 非法字段 | 正常重组合法帧，拒绝非法帧，缓冲占用有上限 |
| T16 | 板 B 重启与显示失联 | 恢复全状态；按 R4 选定策略降级，无永久静音 |
| T17 | 板 A 重启与配置版本不一致 | 新会话不接受旧帧；版本不一致有明确提示 |
| T18 | 首次加载及播放中待机 | 推荐策略首次出声后获 20 秒，初始加载受 32 秒总上限约束；自动切源不续期；兼容策略单独验证 |
| T19 | 活动模式稳定性 | 至少 2 小时、200 次混合操作，无错台、死机、看门狗复位及未解释的持续内存下降 |
| T20 | 同一旋钮的按压与暂缓页面 | 仅旋钮 SW 产生一次按压事件，无独立按键和未实现页面，不切源 |
| T21 | 明确失败或断网与旋转同时发生 | 先选新城，再对新城执行适用降级，旧城事件不得误切新城 |
| T22 | 无错误但主备均缓慢 | 各等待至 15 秒再切源，总首播或错误不超过 32 秒加调度误差 |

15 秒、10 秒、32 秒和 20 秒逻辑边界在模拟时钟中精确校验。实机目标超时误差先取不超过 250 ms；如实际库阻塞造成超差，必须修正实现或把调整后的指标交给 partner 审阅，不用日志中的理论计时冒充达标。输入静音响应目标为 100 ms，也需实测记录。

2 小时测试需要活动模式持续运行，可用明确标记的测试输入维持活动；最终发布需恢复 20 秒待机及明确选定的首次加载策略，不能遗留测试模式。另做无人操作进入待机及长时间待机后唤醒测试。

### 日志和证据

建议日志字段为单调时间、构建版本、session、request、attempt、city、view、audio、source、事件、失败原因、可用堆及 PSRAM。高频 PCM 回调只累计计数，每秒汇总一次，防止串口输出影响音频。

每个用例记录前置条件、操作、期望、实测、版本、执行人和结果。音频首帧、动画 DONE、解除静音、切源和待机应能在同一时间线上核对；听音与屏幕证据可用短视频配合串口日志。无线密码、完整认证令牌等不进入日志。
